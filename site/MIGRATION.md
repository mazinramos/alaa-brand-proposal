# قواعد التحويل إلى Vite

> **المسارات في هذا الملف نسبة إلى مجلد `site/`** داخل ريبو `alaa-brand-proposal`. افتح الريبو، وادخل `site/`، وتشتغل من هناك. كل الأوامر (`npm ...`) تُشغَّل داخل `site/`.

**الهدف:** نفس موقع وشلي بالضبط (شكل، ألوان، نصوص، سلوك)، لكن كمشروع Vite نكمل عليه التطوير. هذه مرحلة **نقل فقط**. أي تحسين أو إصلاح أو ميزة تأتي بعدها.

## المبدأ: صفر تغيير مرئي

الناتج في المتصفح لازم يكون **مطابقاً** للأصل. لو شفت bug في الأصل **اتركه كما هو** وسجّله في `docs/KNOWN-ISSUES.md`.

## المصدر

| الصفحة | الملف الأصلي (للقراءة فقط) | الناتج |
|---|---|---|
| المتجر | `legacy/store.html` | `index.html` + `src/store/` |
| لوحة التحكم | `legacy/admin.html` (النسخة الأحدث من ريبو المتجر) | `admin/index.html` + `src/admin/` |
| مرجع فقط | `legacy/admin-standalone.html` (نسخة قديمة فيها رفع صور، **لا تُحوَّل الآن**) | لا شي |

`legacy/` لا يُعدَّل أبداً. مفاتيح Firebase فيه مخفية (`REDACTED`).

## المسموح

1. نقل `<style>` الداخلي إلى `src/<page>/styles.css` **حرفياً**.
2. نقل `<script type="module">` الداخلي إلى `src/<page>/main.js` **حرفياً**، مع تغيير سطور `import` فقط (انظر 4 و5).
3. نقل Tailwind من سكربت CDN إلى البناء: `import '../tailwind.css'` في `main.js`. الإعدادات في `tailwind.config.js` (جاهزة ومطابقة للأصل). النسخة مثبّتة على 3.4 لأن الأصل كان يستعمل Tailwind 3.
4. مكتبات CDN إلى npm (مثبّتة بنفس إصدارات الـ CDN): `chart.js`, `html2canvas`, `jspdf`. ولو الكود الأصلي يستعمل `Chart` أو `html2canvas` أو `jspdf` كمتغيرات عامة، اجعلها متاحة على `window` عشان بقية الكود يبقى كما هو.
5. استيراد Firebase من روابط `gstatic` إلى `firebase/app` و`firebase/firestore` و`firebase/auth` (نفس الإصدار 12.16.0). الإعدادات تأتي من `src/shared/firebaseConfig.js` بدل القيم المكتوبة.
6. الإبقاء على: وسوم `<head>` (العنوان، meta، الأيقونة)، روابط Google Fonts وFont Awesome، السكربت الصغير لعرض أخطاء JS في اللوحة (يبقى inline في `<head>`)، كل الـ `onclick` الداخلية في الـ HTML.

## ممنوع في هذه المرحلة

- تغيير أي كلاس أو لون أو مسافة أو نص عربي.
- إصلاح bugs أو تحسين الكود أو إعادة تسمية دوال أو تقسيم الملف لوحدات صغيرة.
- تشغيل Prettier أو أي formatter على الكود المنقول (نبي الـ diff مع الأصل صغير وواضح).
- تغيير نموذج البيانات أو أسماء المجموعات في Firestore.
- إضافة مكتبات جديدة أو تعديل `package.json` (المسؤول عنه مهمة 3 فقط).
- تعديل `tailwind.config.js` أو `vite.config.js`. لو احتجت تعديل، اكتبه للمشرف.
- أي كتابة على قاعدة بيانات حقيقية (لا تضغط "إتمام الطلب"، ولا تعدّل في اللوحة).

## اختبار محلي

1. انسخ `.env.example` إلى `.env.local` (ملف غير مرفوع على git).
2. القيم: من ملفات الأصل `Wishly-Store/index.html` (اربط الريبو للقراءة فقط)، سطر `firebaseConfig`. هذه لاختبار القراءة فقط ولا تُكتب في أي ملف مرفوع.
3. `npm install` ثم `npm run dev`، افتح `http://localhost:5173/` للمتجر و`http://localhost:5173/admin/` للوحة.
4. `npm run build` لازم يمرّ بدون أخطاء.

## معيار القبول لكل صفحة

- `npm run build` ينجح بدون تحذيرات جديدة.
- لقطات الشاشة مطابقة للأصل بمقاسات 390 و768 و1366 (التفاصيل في مهمة 3).
- لا توجد أخطاء جديدة في console.
- دفعة JS المنقولة تختلف عن الأصل في سطور `import` وإعداد Firebase فقط.
- الـ `onclick` والأزرار الأساسية تعمل كما في الأصل.

## تقرير التسليم (في آخر رسالتك)

1. الحزم المطلوبة (غالباً: لا توجد حزم جديدة).
2. الملفات المعدّلة (مسارات كاملة).
3. الملفات الجديدة (مسارات كاملة).
4. أي انحراف عن الأصل (وسببه).
5. أوامر التشغيل بالترتيب ورابط المحلي.
6. خطوات اختبار سريعة لما نُقل.
7. أخطاء متوقعة وكيف تتحقق منها.
