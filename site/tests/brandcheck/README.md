# brandcheck: فحص نظافة الهوية

أداة تثبت أن مشروع ألاء **خالٍ من أي أثر للمشروع القديم**. هي الحَكَم في قبول مهام الهوية (راجع `REBRAND.md`). كل الأوامر من داخل `site/`، وتعمل بـ Node فقط (بدون حزم).

## التشغيل

```bash
npm run build                 # لفحص dist أيضاً (اختياري لكنه موصى به)
npm run brandcheck            # الفحص الكامل
npm run brandcheck:selftest   # فحص الأداة نفسها
```

خيارات (بعد `--`): `--no-dist` (بدون dist)، `--summary` (الملخص بدون الجدول التفصيلي)، `--all` (كل الصفوف، الافتراضي أول 200)، `--out=ملف.md` (كتابة التقرير الكامل في ملف).

رمز الخروج: `0` نظيف، `1` فيه نتائج. الرسائل بالعربي.

## ماذا يُفحص

1. **المصدر:** كل الملفات النصية في `site/` المتتبَّعة في git وغير المتتبَّعة (غير المتجاهَلة)، ما عدا الاستثناءات المؤقتة: `node_modules/` و`dist/` و`legacy/` و`tests/parity/` و`tasks/` و`MIGRATION.md` و`REBRAND.md` و`package-lock.json` ومجلد الأداة نفسه. ملفات `.env*` لا تُفحص (غير مرفوعة). هذه الاستثناءات تُقلَّص في التنظيف النهائي (مهمة 5) بتعديل `EXCLUDED_DIRS` و`EXCLUDED_FILES` في `scan.mjs`.
2. **dist/:** لو موجود، يُفحص كله بدون استثناءات.

## الأنماط (أخطاء)

غير حساسة لحالة الأحرف. أنماطها معرَّفة في `patterns.mjs` وتُبنى بالتقطيع حتى لا تكتشف الأداة نفسها.

| المعرّف | ما يكشفه |
|---|---|
| `old-name-en` / `old-name-ar` | الاسم القديم بالإنجليزي والعربي (مع التشكيل والتطويل) |
| `old-name-file` | معرّفات وأسماء ملفات بصيغة الاسم القديم (شرطة أو شرطة سفلية) |
| `old-email-domain` | نطاق الإيميل القديم |
| `old-instagram` / `old-tiktok` | حسابا التواصل القديمان |
| `old-firebase-a` / `old-firebase-b` | معرّفا مشروعي Firebase القديمين |
| `phone-intl` / `phone-local` / `phone-core` | رقم الهاتف أو الواتساب القديم بالصيغ الدولية والمحلية والمختصرة |
| `phone-spaced` | نفس الرقم لو كُتب بمسافات أو شرطات |
| `google-verification` / `google-verification-value` | وسم التحقق من ملكية جوجل وقيمته |
| `wa-link` / `wa-send-link` | أي رابط `wa.me/` أو `api.whatsapp.com/send?phone=` رقمه ليس `ALAA_WHATSAPP_NUMBER` |
| `google-api-key` | أي نص يشبه مفاتيح جوجل (يبدأ بـ AIza) |
| `api-key-literal` | `apiKey` مكتوب نصاً غير فارغ داخل الكود |
| `any-email` | أي إيميل ما عدا الرمز المؤقت (تُتجاهل أسماء الملفات مثل `icon@2x.png`) |

قاعدة روابط واتساب: يُقبل `ALAA_WHATSAPP_NUMBER`، ويُقبل التعبير الديناميكي (`${...}`) فقط لو مصدره `brand` (مثل `${brand.whatsapp}`).

لو تداخلت نتيجتان من نفس العائلة في الموضع نفسه يُبلَّغ عن الأطول أو الأدق فقط.

## التحذيرات (لا تغيّر رمز الخروج)

- **الرموز المؤقتة المتبقية (`ALAA_*`):** عددها وأماكنها، لنعرف ما ننتظره من ألاء.
- **روابط صور Unsplash:** إضافة على المطلوب، لأن `REBRAND.md` يطلب حذف صور المواقع الخارجية.

## قراءة النتائج

الجدول التفصيلي: الملف | السطر:العمود | النمط | النص المطابق (المطابقة بين « »). لملفات `dist/` الصغيرة عدد الأسطر، فالعمود يحدد الموضع في السطر الطويل.

- نتيجة في ملف مصدر: عالجها في مهمة الهوية المعنية (المتجر R1 أو اللوحة R2 أو التوثيق). الأداة **لا تصلح** شيئاً.
- نتيجة في `dist/` فقط: أعد البناء بعد إصلاح المصدر، فإن بقيت فالمصدر هو السبب أو متغير بيئة مثل `VITE_FIREBASE_API_KEY` حُقن وقت البناء.
- `any-email` أو `google-api-key` في `dist/` من مكتبة خارجية: لا تُستثنى تلقائياً، أبلغ المشرف ليقرر استثناءً موثّقاً.

## الفحص الذاتي

`npm run brandcheck:selftest` ينشئ مجلداً مؤقتاً فيه عيّنة لكل نمط، وملفاً نظيفاً، ومجلدات مستثناة، ومجلد `dist`، ويتأكد أن كل نمط يُكتشف وأن النظيف يمر وأن المستثنى لا يُفحص.
