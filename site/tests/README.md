# أداة فحص المطابقة (Parity)

تثبت أن موقع Vite **مطابق** لموقع وشلي الأصلي (`legacy/`). كل الأوامر تُشغَّل من داخل `site/`.

## المتطلبات

1. Node 22 أو أحدث، ثم `npm install`.
2. متصفح Chromium لـ Playwright (مرة واحدة على الجهاز):

   ```bash
   npx playwright install chromium
   ```

   (أو `npm run parity:browser`). على Linux قد تحتاج أيضاً `npx playwright install-deps chromium`.
3. ملف `.env.local` في `site/` (غير مرفوع على git):

   ```bash
   cp .env.example .env.local
   ```

   املأ قيم Firebase من سطر `firebaseConfig` في ريبو المتجر (**للقراءة فقط**). الأداة تعوّض بها `REDACTED` في ملفات `legacy/` وقت التحميل فقط، ولا تعدّل الملفات.
4. اتصال بالإنترنت: الأصل يحمّل Tailwind وFirebase وخطوطاً من CDN، ويقرأ المنتجات الحقيقية من Firestore.

اختياري: أضف `TEST_ADMIN_EMAIL` و`TEST_ADMIN_PASSWORD` في `.env.local` ليدخل اللوحة ويلتقط كل تبويب. الضغطات الوحيدة المسموحة هي زر الدخول وأزرار التنقل داخل `#adminNav`. لا يضغط أي زر حفظ أو حذف أو "إتمام الطلب"، ولا يكتب على القاعدة.

## التشغيل

| الأمر | ما يفعله |
|---|---|
| `npm run parity` | الأصل مقابل Vite: يبني Vite ويشغّل `vite preview` على منفذ حرّ، ويقارن |
| `npm run parity:self` | الأصل مقابل نفسه: **المتوقع نجاح كامل**. يتأكد أن الأداة والبيئة سليمتين |
| `npm run parity:selftest` | فحص الأداة نفسها بدون إنترنت وبدون Firebase (صفحات تجريبية في `tests/parity/fixtures`) |

خيارات إضافية (بعد `--`): `--dev` (vite dev بدل preview)، `--skip-build`، `--tolerance=0.2` (نسبة البكسل المسموحة)، `--pages=store,admin-login`، `--viewports=390,1366`، `--no-freeze` (إلغاء تجميد Date)، `--no-admin`.

مثال: `npm run parity -- --pages=store --viewports=1366`

متغيرات متقدمة (للـ CI): `PARITY_CHROMIUM_PATH` لمسار متصفح جاهز، `PARITY_BROWSER_ARGS` لوسائط التشغيل (مثل `--no-sandbox`).

رمز الخروج: `0` نجاح، `1` فشل في فحص أو أكثر، `2` توقف لخطأ إعداد (مثل غياب `.env.local`، أو فشل تحميل الأصل، أو فشل بناء Vite) مع رسالة بالعربي.

## ما يُفحص

لكل صفحة (المتجر، شاشة دخول اللوحة) وبالمقاسات 390 و768 و1366:

1. **لقطة كاملة** للأصل ولـ Vite، ومقارنة بالبكسل (معادلة pixelmatch نفسها، بدون مكتبة إضافية) مع صورة فرق (أحمر = اختلاف). تُحسب الأبعاد المختلفة فشلاً.
2. **نص الصفحة** (`innerText`) سطراً بسطر.
3. **عدد العناصر** داخل `body` (بدون script وstyle).
4. **أخطاء console**: أي خطأ جديد في Vite غير موجود في الأصل يُفشل الفحص.
5. **طلبات الشبكة الفاشلة** (حالة 400 فما فوق أو فشل اتصال): نفس القاعدة.
6. **كلاسات Tailwind**: كل كلاس له قاعدة CSS فعلية في الأصل لكنه بلا قاعدة في Vite يُفشل الفحص (يكشف الكلاسات التي لم تُولَّد في البناء).

لتجنب اختلافات كاذبة تفعل الأداة في الجهتين: إخفاء animations وtransitions، تمرير الصفحة لتفعيل `reveal` والصور الكسولة، انتظار هدوء الشبكة وأول طلب Firestore واستقرار الـ DOM، تعطيل المؤقتات الطويلة (3 ثوانٍ فأكثر، مثل تدوير التقييمات)، وتجميد `Date` في المتجر (العدّ التنازلي للعروض).

## قراءة النتائج

المخرجات في `tests/parity/output/` (غير مرفوعة على git):

- `report.md`: جدول (الصفحة | المقاس | نسبة الاختلاف | نجاح/فشل | صورة الفرق | السبب)، ثم جدول تفصيل الفحوص، ثم تفاصيل كل فشل.
- `screenshots/`: لقطات الجهتين. `diffs/`: صور الفرق (تُولَّد فقط عند وجود اختلاف).
- `results.json`: النتائج الخام.

كيف تفسّر الفشل:

| الفشل | المعنى المحتمل |
|---|---|
| البكسل فقط بنسبة صغيرة | فروقات خطوط أو antialiasing. جرّب `--tolerance`، وراجع صورة الفرق |
| البكسل مع اختلاف الأبعاد | تغيّر تخطيط أو كلاس مفقود أو CSS لم يُنقل |
| النص أو العناصر | ملف HTML أو `main.js` لم يُنقل حرفياً |
| console أو الشبكة | خطأ استيراد، مفتاح Firebase خاطئ، أو مورد ناقص |
| Tailwind | كلاس لم يولّده البناء: تحقق من `content` في `tailwind.config.js` (الملفات تُعدَّل عبر المشرف) |
| فشل كل الصفوف بفروق ضخمة | الصفحة ما زالت placeholder (مهمة 1 أو 2 لم تكتمل بعد). هذا متوقع |

## حدود

- يفحص الحالة الأولية للصفحة فقط، لا الحالات الناتجة عن تفاعلات.
- البيانات حيّة من Firestore: تغيّرها بين لقطة الأصل ولقطة Vite قد يعطي اختلافاً كاذباً. أعد التشغيل للتأكد.
- Font Awesome وخطوط Google من نطاق آخر ولا تُقرأ قواعدها، فلا تدخل في فحص Tailwind.
- الصفحات الأطول من حد Chromium للقطة (حوالي 16,000 بكسل) تُقتطع بنفس الطريقة في الجهتين.
