# مهمة 5: المراجعة والتكامل (المرحلة 2)

> **المسارات في هذا الملف نسبة إلى مجلد `site/`** داخل ريبو `alaa-brand-proposal`. افتح الريبو، وادخل `site/`، وتشتغل من هناك. كل الأوامر (`npm ...`) تُشغَّل داخل `site/`.

> **لا تبدأ إلا بعد ما المشرف يدمج مهام 1 و2 و3 و4 في `main`.** المشرف ح يخبر صاحب المشروع. لو `main` ما فيه `src/store/main.js` و`src/admin/main.js` و`tests/parity`، توقف وأخبره.

- **الـ branch:** `acct-5-review` (من آخر `main`)
- **المسموح لك:** تصحيح الانحرافات في أي ملف من ملفات التحويل (`index.html`, `admin/**`, `src/**`) **بشرط أن يكون الإصلاح لإعادة المطابقة مع `legacy/` فقط**، و`docs/REVIEW.md`
- **اقرا أولاً:** `MIGRATION.md`, `docs/KNOWN-ISSUES.md`

## المطلوب

1. **مراجعة نصية:** لكل من المتجر واللوحة، اعمل `diff` بين السكربت/الستايل الأصلي (المستخرج من `legacy/`) والملف المنقول. اشرح كل فرق: مقبول (import/config) أو انحراف.
2. **تشغيل الفحص:** `npm install && npm run build && npm run parity`، واقرأ التقرير وصور الفرق بعينك.
3. **تصحيح الانحرافات** مع commit مستقل لكل واحد ورسالة واضحة، بدون تحسينات خارج المطابقة.
4. **فحص يدوي** للتدفقات الرئيسية بعين المستخدم (قراءة فقط): تصفح، سلة، معاينة، شاشة دخول اللوحة. وبدون كتابة بيانات.
5. **`docs/REVIEW.md`:** جدول: البند | الحالة (مطابق / انحراف تم إصلاحه / انحراف باقٍ) | الدليل. وقرار نهائي: **جاهز للاعتماد** أو **غير جاهز** مع الأسباب.

## قيود

- لا تحسّن ولا تصلح bugs الأصل (هذي في `docs/KNOWN-ISSUES.md`).
- لا تغيّر الأصل في `legacy/`.
- لو الفحص يحتاج حساب أدمن ما عندك، قل ذلك وصنّف تبويبات اللوحة "غير مفحوصة".
